# Customs: CN23, EORI, GST, DDP

Applies to international shipments and shipments to French overseas
territories. This repo currently builds CN23 declarations for non-EU
international shipments per `CLAUDE.md` — this doc is the field-level spec
behind that logic.

## CN23 document

- Mandatory for customs clearance to int'l destinations and some special
  territories.
- Auto-generated by `generateLabel` when customs data is supplied — no need
  to call `generateCN23` separately in the normal flow.
- Returned in the MTOM PDF attachment alongside the shipping label.
- If CN23 data is missing/incomplete, the WS returns an **ERROR** and no
  label is produced — validate all customs fields before calling.
- Must physically travel with the parcel (4 printed copies) except when
  electronically declared.

## `customsDeclarations` REST JSON structure (current repo)

```json
// in letter.service:
"service": {
  "productCode": "DOS",
  "depositDate": "2026-08-12",
  "transportationAmount": 24.99,   ← frais de port (obligatoire CN23, erreur 30020 si absent)
  "orderNumber": "..."
}

// in letter.customsDeclarations:
"customsDeclarations": {
  "includeCustomsDeclarations": true,   ← booléen (pas entier)
  "contents": {
    "article": [
      {
        "description": "Product name (English for US)",
        "quantity": 1,
        "weight": 0.500,
        "value": 25.00,
        "hsCode": "123456",           ← optionnel, 6 chiffres min
        "originCountry": "FR"
      }
    ],
    "category": { "value": 3 },       ← objet complexe, PAS un entier direct
    "explanations": "..."             ← optionnel, texte libre
  }
}
```

Notes:
- `transportationAmount` va dans `service`, pas dans `customsDeclarations` ni `parcel`.
- `category` est un **objet** `{ value: int }` à l'intérieur de `contents`.
- `explanations` est à l'intérieur de `contents`, pas au niveau de `customsDeclarations`.
- `includeCustomsDeclarations` est un **booléen** `true`, pas l'entier `1`.
- `hsCode` est optionnel mais recommandé ; 6 chiffres minimum.
- `originCountry` est ISO 2 lettres.
- `totalAmount` et `shippingAmount` n'existent PAS dans `customsDeclarations` — ils
  n'appartiennent pas à ce niveau dans le schéma REST officiel.

### `category` field (shipment type)

| Value | Meaning |
|---|---|
| 1 | Gift |
| 2 | Commercial sample |
| 3 | Commercial parcel |
| 4 | Document |
| 5 | Other |
| 6 | Return of goods |

### `value` field
Unit value of articles in EUR, max 2 non-zero decimals. Sum of all article
values must be ≥ 1.

### `hsCode` (tariff/HS code)
Recommended (mandatory for postal shipments per international norms) —
6-digit minimum. Speeds customs clearance. Not looked up by the WS; source
externally (customs office or EU TARIC consultation tool).

## EORI (EU shippers, non-EU destinations)

Required for any EU professional shipping outside the EU.

REST JSON (at request root, same level as `letter`):
```json
"fields": {
  "field": [
    { "key": "EORI",          "value": "FR12345678901234" },
    { "key": "EORI_ADDRESSEE","value": "xxxxxxxxxxxxxxxxxx" }
  ]
}
```

Both appear on the CN23 when supplied. Missing sender EORI on a shipment
that requires it → error `30561`. Sender EORI is stored in
`CarrierConfig.senderConfig.eori` and passed automatically by the label route.

## GST (Australia)

REST JSON (inside `fields.field[]` at request root):
```json
{ "key": "GST", "value": "xxxxxxxxxxxxxxxxxx" }
```
Required for trade shipments to Australia; the exporter remits GST directly
to the Australian tax authority.

## DDP (Delivered Duty Paid)

### International DDP
- Set `ddp` = `true`/`1` at the WS SLS entrance.
- Destination country + product must be DDP-eligible (check Colissimo site)
  or the WS returns error `30328`.
- **US/Canada shipments:** `stateOrProvinceCode` is mandatory. FedEx
  cross-checks postcode vs. state/province — mismatch → error `30224`.
- Package dimensions (length/width/height) mandatory → missing/invalid
  triggers one of errors `30329`–`30335`.
- Recipient phone number mandatory → missing triggers `30220`.
- `CustomsDeclarations.description` must be in **English** and is
  mandatory → missing triggers `30557`.

### Overseas DDP (formerly "free of taxes and duty", `ftd` flag)
- Set `ftd` = `true`/`1`.
- Available for Guadeloupe, Martinique, Mayotte, Réunion, Guyane (excludes
  Saint-Pierre-et-Miquelon).
- Not available for Consumer OnLine products.
- Compatible with `CDS` product code.

### US-specific rules (post-Aug-2025 customs changes) when shipping
**without** DDP:
1. Shipper's EORI number required.
2. Destination address as 2-letter state/province code.
3. Recipient mobile phone number required.
4. Customs item descriptions must be in English.

### UK DDP restrictions
- Only category "Sales of goods" is eligible for DDP to the UK
  (else error `40022`).
- Total shipment value must be between £135 and £900 (error `40023`
  otherwise).

## Country/postal code validation

- `countryCode`: ISO 3166 (2-letter). **Special territories use their own
  code, not the parent country's** — e.g. Greenland is `GL`, not `DK`.
- `zipCode`: format is validated against the destination country's mask
  (e.g. Canada requires 6 characters). Mismatch between postcode and
  country → `30212`/`30213`-class errors.
- `stateOrProvinceCode`: required for US (and some other countries per
  regulation). Mismatch with postcode → `30224`.
- Use `getProductInter` to check valid return options per destination
  country before offering them in the UI.

## Reference: known customs-related error codes

See `error-codes.md` for the full table. Frequently-relevant ones for this
repo's flow: `30500`–`30561` (article/customs content errors), `30328`
(DDP ineligible), `30224` (postcode/state mismatch), `40022`/`40023` (UK
DDP), `30326` (FTD option invalid).
